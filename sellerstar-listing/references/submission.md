# 审核、提交与沃尔玛回执

## 审核

从暂存区定位本次 SKU 和目标店。用「查看并审核」展开工作稿，检查商品身份、规格和数量、图片与实物、文案与属性、售价和库存。保存人工修复后重新打开确认。

用户要求审核时，可逐件审核或在「批量人工审核」对目标记录多选或全选。已经实际核对的检查项才能勾选，完成后查每条审核记录。审核窗口里的全选只作用于该窗口列出的商品。区分平台类目预检与人工审核。

提交未审核商品时，页面可能提示「存在 N 个 LISTING 未进行人工审核，是否直接提交」。用户批准跳过本次所列商品的人工审核，且当前商品版本、店铺和数量吻合时，可选「继续提交」。需要审核就选「去审核」，处理弹窗列出的商品，再回提交。产品仍会校验当前版本和提交前置条件。

## 提交

1. 明确是正式提交，且目标站点、店铺及 SKU 范围已授权。再次核对上架方式（新建或跟卖）、商品标识、实际价格库存、类目和图片。按真实店铺分别提交，内置 `submit_listing_staging` 每次最多 50 条，门户以页面实际限制为准。
2. 使用「提交选中到 Walmart」或已发现的内置提交工具。核对确认框、错误汇总和结果清单。若页面支持部分提交，让符合条件的 SKU 继续，有问题的留在工作稿。逐项记录最终发送、明确未发送、失败与待核状态。
3. 填写缺少或不合法字段时，依据当前商品资料和官方类目规范，保留字段值来源。可依据证据使用页面 AI 修复或集中填写，保存后逐 SKU 复查。读回已提交的 SKU，后续仅针对已明确失败或未发送的修正项操作。

## 核对与恢复

| 可见结果 | 含义和下一步 |
| --- | --- |
| 暂存、待补资料、待审核 | 继续处理现有稿或按用户终点交付 |
| `not_sent` / 明确未发送 | 先查确切拒绝原因和原记录。修复并读回后，仅对已证实未发送的范围再走授权提交 |
| 已提交、排队中、处理中 | 保存 Feed ID、实际发送 SKU 与时间。用「上架回执」定位同批，查逐 SKU |
| 部分成功、部分失败 | 逐项记录。若使用「只退回失败 SKU」或页面同义入口，先核对是否已经在暂存、是否存在更晚 Feed、是否是明确失败 SKU |
| Feed 已接收 | 记录平台接受结果。目标要求「确认上架」时，在「在线商品」用同店、同 SKU 查平台发布状态 |
| 超时、响应丢失、`needs_review`、提交中或缺少 Feed ID | 先读原任务、暂存提交历史、Feed 详情和同店同 SKU。缺 Feed 不足以证明没有发送。按产品对账入口核对，等待时保留原请求，不再次点提交 |

「刷新状态」是平台代理查询并更新本地回执，页面需要时用，保留旧 Feed ID 与读取时间。发现类目、无效字段或图片拒绝时定位报错的具体 SKU，并用当前规格或图链接与旧提交对照。「已接收」和「已发布」各自用所在页面或真实回执证明。

交付字段以实际发生为准。记录 `店铺 / 站点`、`任务 ID`、`SKU 与暂存 ID`、`Feed ID`、`本地 / 平台状态`、`失败原因及修复`、`核对时间` 和 `已知费用`。
