# 铺货任务、SOP 与暂存

## 创建或续跑

1. 打开「铺货任务」，从最近任务或工作台找到同批目标。按店铺、任务 ID、源商品标识和 SKU 复核。已有任务时打开原任务检查状态。
2. 需要新任务时点「新建铺货任务」，使用「从采集箱选择」。采集插件同步完成后刷新列表。已有可用商品表格时，可走产品页面的「上传表格」。操作范围为部分变体时用可用的子 SKU 选择或独立子链接。用任务名称和选中清单确认后，点「创建任务并生成计划」。创建成功后回读实际展开的 SKU、主图和采集价。
3. 在「检查类目」或沃尔玛类目列核对官方 Product Type。仅在同类商品证据一致时批量设为同一官方类目。单件类目修复保存后重新查实际类目必填。来源名称、英文单复数或旧回执的伪字段都可能与当前官方规格不同。
4. 在「本批处理规则」核对目标店铺与站点、每 SKU 售价规则、库存规则、品牌、是否重写文案、是否补属性、图片方式、上架方式和交付位置。按倍率时比较每个 SKU 的实际来源价与最终舍入值。按用户批准的品牌与属性，保留有证据的人工值。按 SKU 读取预估积分，生成图需确认档位和费用。
5. 完成后停在暂存的任务，交付选「放入上架暂存区」。核对「确认计划并开始」包含的阶段和费用再执行。无须发布的路径可一直停在暂存，含待补资料的稿也保留可提交前修复的状态。

## 看状态和处理失败

- 进任务商品详情用「查看并处理」，看来源图、最终图、规则、执行实况和逐项错误。按报错定位真实字段，先修再保存，刷新详情回读。如果重新加载仍是旧值，查是否保存成功或是否编辑的 SKU/版本已切换。
- 续跑一件选择对应商品并点「继续此商品」。已有运行中或暂停的任务应先读真实状态。多件暂停后只勾选本批需要继续的商品，使用「批量开始」，回读实际启动、跳过和等待结果。只有明确整批授权才走整批启动。
- 已确认失败修好后重试同一商品。待核对的模型或平台步骤先查扣点、任务或平台回执。有新证据才续跑。受影响的 SKU 单独处理，继续能够处理的商品。
- 生成文案前核对已确认尺寸和商品身份。尺寸依次使用当前 SKU 的清晰图中标注、标题、详情；未能确认的字段留空。区分包装尺寸、整件尺寸、部件尺寸和单位。图片或属性补齐保持当前颜色、尺码和套件数量。
- 如需要独立生图，在「AI生图」核对目标店铺、SKU 和原图，查看明确的费用及图型，取得任务 ID 后读回结果。人工选择合格图并检查绑定后，使用页面的回填入口。回到商品详情确认主副图，暂存及发布按本任务原授权执行。

## 暂存验收

从当前任务的「上架暂存区」或左侧全局「暂存区」按目标店铺、SKU 找实际记录。列表可能同时显示其他任务的商品。用来源、变体和暂存 ID 对照此次范围，检查标题、价格、库存、类目、属性、图片及保存状态。使用历史回执定位具体字段时，区分旧错误与当前已保存的值。需补资料的 SKU 留在原工作稿，报告确切字段及证据缺口。

若用户只要求暂存，到这里按 SKU 交付任务 ID、暂存数量、已处理/待处理状态和实际积分。需要审核或提交时继续 [审核、提交与回执](submission.md)。
